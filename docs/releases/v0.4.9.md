# WorldForge v0.4.9

This patch adds browser security headers and Node.js 24 support for source installations. Docker image availability is confirmed by the **Release Docker image** workflow and the digest it adds to the GitHub release.

## Changes since v0.4.8

- A `Permissions-Policy` header disables unused browser features, including access to the camera, microphone, geolocation, and payment APIs.
- The development lint toolchain uses a patched `minimatch` for [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249).
- Git ignores the repository-root `backups/` directory to prevent accidental commits. This does not restrict filesystem access to backups or untrack files committed previously.
- Source installations support Node.js 22 and 24 with `better-sqlite3` 12.11.1. The Docker image still uses Node.js 22. For native source installations, use `pnpm sqlite:build` after installation to build the patched SQLite engine.

## Upgrade and rollback

No schema migrations, configuration changes, or data backfills are required from v0.4.8. Before upgrading, stop WorldForge and back up the database and asset directory together. Keep the existing volume, Compose project name, origin, and proxy settings.

After image publication, set `WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.9` in your pull-only Compose deployment. Run `docker compose pull` and `docker compose up -d --wait` with the same Compose files you normally use. Verify login and a representative world and image. To roll back, stop the app, restore the matched pre-upgrade backup, and restart with your previous image. Do not remove the data volume.

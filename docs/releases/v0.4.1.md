# WorldForge v0.4.1

This is the first release prepared for versioned Docker Hub publication at
`emorgan33/worldforge`. Image availability is confirmed only after the
**Release Docker image** workflow succeeds. The GitHub release notes are then
updated with the exact image version and digest.

## Highlights since v0.4.0

- Versioned Docker image publishing, a pull-only Compose file, isolated image
  startup checks, and install/upgrade/release documentation. Initial supported
  image architecture: **linux/amd64**.
- Installation administration for accounts, roles, status, sessions, recovery,
  and audited account deletion. Administrators can resolve owned-world
  deletion blockers by transferring ownership or separately confirming the
  purge of an archived world. Deletion still rejects remaining durable records.
- Interactive map drawing tools with labels, lines, shapes, freehand strokes,
  an eraser, layers, and chronological rendering.
- The Night Watch author workspace, refreshed screenshots, improved login/setup
  contrast, and expanded operator wiki guidance.
- Stock-art selection/provenance/credits/advisory infrastructure. All eight
  installed candidates remain pending human rights and design review;
  production stock selection remains disabled for those candidates.
- Supporting migration and recovery improvements for map ordering, durable
  world imports, reader search, and administration.

## Install a published image

After image publication succeeds, a fresh install needs Docker Compose and curl,
not a repository checkout:

```bash
mkdir worldforge && cd worldforge
curl -fsSLo compose.yml https://raw.githubusercontent.com/emorgan33/worldforge/v0.4.1/docker-compose.release.yml
cat > .env <<'EOF'
WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.1
WORLDFORGE_ORIGIN=http://localhost:3033
WORLDFORGE_TRUSTED_PROXY=0
EOF
docker compose pull
docker compose up -d --wait
docker compose exec worldforge pnpm auth:setup
```

Open the printed setup link privately, then sign in at `http://localhost:3033`.
For public HTTPS, configure the canonical origin, trusted proxy, and private
app port using the [deployment guide](https://github.com/emorgan33/worldforge/blob/v0.4.1/docs/deployment-configuration.md).
Do not use the fresh-install commands to replace an existing deployment's
project, volume, or proxy configuration.

## Upgrade and migrations

**Stop WorldForge and take an integrity-checked backup of both the SQLite
database and full asset directory before upgrading.** Follow
[Backup and restore](https://github.com/emorgan33/worldforge/blob/v0.4.1/docs/backup-restore.md).
Keep the same Compose project name, named volume, and any proxy overrides.

Compared with `v0.4.0`, this release includes nine additional migrations:

- `20261023090000_map_elements`
- `20261023150000_stock_art_provenance`
- `20261023160000_placement_alt_fields`
- `20261023170000_asset_restriction`
- `20261023200000_pending_stock_review`
- `20261024120000_map_element_order`
- `20261024133000_world_transfer_import_requests`
- `20261025120000_r17_reader_search_indexes`
- `20261030120000_installation_admin_p1`

Container startup validates configuration, applies pending migrations, and
then starts the application. Do not bypass a failed migration. An installation
already tracking current `main` may have these migrations applied; the
packaging change itself introduces no additional schema migration.

For an existing published-image installation, set
`WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.1` in `.env`, then run:

```bash
docker compose pull
docker compose up -d --wait
docker compose logs worldforge
```

For an existing source-build installation:

```bash
git fetch --tags
git checkout v0.4.1
docker compose up -d --build
docker compose logs worldforge
```

To switch from source builds to the published image, explicitly select
`docker-compose.release.yml` and every required proxy override, preserving the
existing project/volume. Do not run `down --volumes` against real data.
Existing storage must be writable by UID/GID `10001`; see the deployment guide
before changing ownership. Do not run the demo seed on existing content.

After upgrading, confirm the container healthcheck, login, representative
worlds/articles/readers/images, and a write using your normal permissions.
Account/ownership administration remains separately authorized and audited.

## Rollback and limitations

Restore the pre-upgrade database and matching assets while the service is
stopped, then select the image/source version recorded with that backup. An
older image alone is not a safe rollback after schema migration.

- ARM64 images are not included in this release.
- Stock-art candidates are not approved for production selection.
- Character sheets are manual-entry tools (apart from D&D ability modifiers),
  not full character builders.
- No long-term-support branch is provided. Pin a version or digest, read
  subsequent release notes, and maintain off-host backups.

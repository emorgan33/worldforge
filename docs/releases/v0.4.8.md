# WorldForge v0.4.8

Player portal navigation update with container dependency and release-workflow
fixes. Image availability is confirmed only after the **Release Docker image**
workflow succeeds and the image tag/digest appears in the GitHub release notes.

The `v0.4.6` image was blocked by a fixable HIGH dependency finding, and the
`v0.4.7` publish step rejected the non-native ARM64 archive after Docker reported
its manifest digest instead of its config digest. Neither version published an
image. Use `v0.4.8` for published-image installations.

## Highlights

- Adds a **Back to main site** link to the `/player` header. The link uses the
  same-origin `/` target, stays visible on desktop and narrow screens, and has a
  keyboard-accessible text label plus a focus indicator.
- Overrides `@prisma/config`'s `effect` dependency from `3.21.0` to `3.22.1`,
  addressing `CVE-2026-121707`.
- Accepts the hash-verified archive's manifest digest only when Docker reports it
  for a non-native image, then normalizes to the tested config digest before
  publishing. Native images keep the existing content-identity check.
- Existing player authentication, campaign membership, and resource access rules
  are unchanged. The link grants no additional access.
- No application data-model, API, or schema changes are included relative to
  `v0.4.5`.

## Security notes

This release is **not vulnerability-free**. The image is rebuilt from this tag,
and the release workflow blocks fixable HIGH/CRITICAL findings before publishing.
Unfixed findings remain visible in the retained scan reports.

See [Container security](https://github.com/emorgan33/worldforge/blob/v0.4.8/docs/container-security.md)
for policy, evidence, limitations, and local scan commands. The workflow report
for this exact release is authoritative if counts differ from earlier releases.

## Upgrade

No schema migration is added relative to `v0.4.5`.

**Stop WorldForge and take a verified backup of both the SQLite database and the
full asset directory before upgrading.** Keep the same Compose project name,
`worldforge-data` volume, UID/GID `10001`, origin, and proxy settings.

For a published-image installation, set
`WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.8` in `.env`, then run:

```bash
docker compose pull
docker compose up -d --wait
docker compose logs worldforge
```

For a source-build installation:

```bash
git fetch --tags
git checkout v0.4.8
docker compose up -d --build
```

Native source deployments that want the patched SQLite engine must run
`pnpm sqlite:build` after installing dependencies; ordinary `pnpm install`
leaves the driver's bundled SQLite in place. The supported Docker image always
builds SQLite 3.54.1.

Verify login, the player portal and **Back to main site** link, representative
worlds/articles/search/images, a normal write, and backup tooling after
upgrading. Rollback requires the older image/source **and** the matching
pre-upgrade database-and-assets backup. Do not run an older application against
a database that has received newer migrations, and do not use `down --volumes`
on real data.

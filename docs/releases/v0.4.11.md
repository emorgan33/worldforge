# WorldForge v0.4.11

This release adds selectable interface themes, a paper-inspired D&D 5e character
sheet, an admin header that identifies the running build, and fixes for
production rendering and the world settings editor. Image availability is
confirmed by the **Release Docker image** workflow and the digest it adds to the
GitHub release.

## Highlights

- **Six interface themes.** Night watch, True black, Daylight, Pathfinder, D&D,
  and Match system. The choice is saved to your account and follows you across
  devices.
- **Themes everywhere.** The Theme control appears in the author workspace,
  admin pages, player portal, sign-in, setup, and public/campaign reader pages.
  Invitation pages follow the stored theme but do not show the control.
- **World presentation is unchanged.** Article paper, ink, accent, reading width,
  and custom CSS still come from each world's own appearance settings.
- **Paper-inspired D&D character sheets.** D&D 5e 2014 sheets now use a
  parchment-style layout; Pathfinder 2e Remaster sheets are unchanged.
- **"Running build" in Administration.** Administrators can confirm the version
  and commit serving the live site without server access.
- **Production page fixes.** Database-backed pages render at request time again,
  and the world settings form no longer reopens on return.

## Changes since v0.4.10

### Interface themes

- New **Interface theme** dropdown with six choices: Night watch (default,
  unchanged), True black, Daylight, Pathfinder, D&D, and Match system.
- Themes apply to the workspace shell, admin pages, player portal,
  authentication and setup pages, dialogs, menus, editors, tables, and form
  controls. Reader/player pages also get a server-rendered theme control so
  anonymous visitors can choose a theme; invitation pages follow the stored
  theme without a control.
- **True black** is an OLED-friendly dark palette: pure black canvas, raised
  surfaces above black, and near-white (not pure white) text to limit halation.
- **Daylight** is a neutral warm light palette, audited for contrast across
  workspace, admin, player, and reader chrome.
- **Pathfinder** and **D&D** are colored light palettes derived from the
  existing reader world themes, so a campaign using that theme and a viewer
  using the matching chrome theme see consistent paper, ink, and accent colors.
  These reuse color values only; no publisher logos, wordmarks, fonts, or
  artwork are included. Pathfinder and D&D chrome use light surfaces on a
  slightly darker canvas, so depth comes from borders and shadows.
- **Match system** follows the operating system's light/dark preference,
  including live changes without a reload.
- Signed-in theme changes update the account value and the device cookie in one
  response. Sign-in refreshes the device cookie from the account, so the account
  choice always wins. Anonymous visitors use the cookie; unknown values fall back
  to Night watch.
- Fixed fixed-colour chrome such as modal scrims, white/black labels, reader
  search fields, editor surfaces, and article chrome so light themes stay
  readable. Map annotation colours, character-sheet paper, and the legacy
  `#eab308` fallback remain author data and are unchanged.
- Added a token guard (`pnpm check:tokens`, run in CI) that rejects raw palette
  utilities and fixed black/white chrome colours outside an allowlist of
  content files.

### D&D 5e character sheet

- D&D 5e 2014 character sheets now use a parchment-style layout with grouped
  identity, ability, defence, equipment, spellcasting, and personality areas.
- Pathfinder 2e Remaster sheets, stored sheet values, row extensions, local
  drafts, revisions, and export/import data are unchanged.
- These remain manual-entry sheets: only D&D ability modifiers are calculated.

### Administration

- The admin header now shows **Running build** with the package version and
  short Git revision, plus a `modified source` marker for builds made from a
  working tree with uncommitted tracked changes. `revision unknown` is shown
  rather than guessing when no revision was recorded. The label is only rendered
  after the administrator access check.
- Admin pages gained the **Interface theme** control.
- Release images pass the same CI-verified revision used for the OCI label, and
  the release smoke check now verifies the runtime build metadata and rejects
  dirty release builds.

### Fixes

- **Database-backed pages render at request time.** Reader, campaign, player,
  workspace, and admin pages declare a request-time boundary before querying.
  Without it, the partial-prerender build ran queries during prerendering and
  Next.js aborted routes on Prisma's clock read, producing the prerender error
  page in production builds (not reproducible under `next dev`).
- **World settings no longer reopen.** Opening **Edit world & styling** from the
  World settings & GM tools card used a persistent counter that was never
  consumed, so Campaign home reopened the form after navigating away, after
  cancel, and after switching worlds, and reported a false dirty state. The
  request is now one-shot (#50).
- **Daylight contrast fixes.** Sidebar controls use a visible strong outline
  instead of the decorative divider, and light-mode headings, labels, and search
  borders use the correct palette values.

### Documentation

- Added a themes feature record, updated the wiki theme page, the README theme
  note, and the theme switcher help text.
- Added deployment instructions for verifying the running build and passing
  `WORLDFORGE_BUILD_REVISION` to source-built Compose images.
- Corrected the backup and restore helper commands: they run as container root
  so the backup directory is writable, and restore now restores UID/GID `10001`
  ownership and `700`/`600` permissions on the database and assets.
- Documented the request-time rendering rule for Server Components versus Route
  Handlers.

## Compatibility

- One migration: `User.theme TEXT` (nullable). Existing accounts keep the
  default Night watch appearance; no backfill is required.
- New endpoint `POST /api/preferences/theme` for saving the theme choice.
- No database data format changes, no API removals, and no configuration keys
  are required.
- Optional: source-built container images can set
  `WORLDFORGE_BUILD_REVISION=<commit>` when building so the admin header reports
  the revision. Published images set it automatically.
- Night Watch remains the default and was audited to render identically; its
  pre-existing sub-3:1 decorative text values are unchanged.
- The container still runs Node.js 22 and SQLite 3.54.1.

## Upgrade and rollback

Stop WorldForge and back up the database and asset directory together before
upgrading. Keep the existing volume, Compose project name, origin, and proxy
settings.

After image publication, set `WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.11` in
your pull-only Compose deployment, then run `docker compose pull` and
`docker compose up -d --wait` with the same Compose files you normally use. The
startup entrypoint applies the pending `User.theme` migration. Verify login, a
representative world and image, and that the theme dropdown changes the
interface.

To roll back, stop the app, restore the matched pre-upgrade database and assets
backup, and restart with your previous image. Do not remove the data volume. An
older image ignores the extra nullable column, but restore the backup anyway so
the database matches the release you are running.

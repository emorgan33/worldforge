# WorldForge v0.4.10

Packaging-only patch. The application code is identical to v0.4.9; this release
publishes it with a corrected release workflow. Image availability is confirmed
by the **Release Docker image** workflow and the digest it adds to the GitHub
release.

## Changes since v0.4.9

- The publish job records the platform image manifest digest that the release
  index references. A platform push can publish an OCI index that wraps the
  platform image manifest with build attestations; recording the wrapper digest
  made the first post-publication verification fail for AMD64 in `v0.4.8` and
  `v0.4.9`, which then required a rerun. Malformed, ambiguous, or unexpected
  pushes now fail closed instead.
- The release index now references the platform image manifests directly, so the
  optional build attestation manifests are no longer carried into it.

## Compatibility

- No application data-model, API, or schema changes relative to `v0.4.9`.
- No new migrations, configuration keys, or backfills.
- The container still runs Node.js 22 and SQLite 3.54.1.

## Upgrade and rollback

`v0.4.9` is already a fully verified multi-platform release, so moving to
`v0.4.10` changes only the packaging record. Upgrade by setting
`WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.10` in your pull-only Compose
deployment, then run `docker compose pull` and `docker compose up -d --wait`
with the same Compose files you normally use.

Stop WorldForge and back up the database and asset directory together before
changing images. Verify login and a representative world and image afterwards.
Rollback needs the older image and the matching pre-upgrade backup; do not
remove the data volume.

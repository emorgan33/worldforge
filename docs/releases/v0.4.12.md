# WorldForge v0.4.12

This release turns the campaign reader into a usable player workspace — shared
maps, a "What's new" feed, private bookmarks, and a private notebook — and adds a
substantial security-hardening pass across request limits, access checks,
deployment boundaries, container privileges, logging, and backup recovery.
Image availability is confirmed by the **Release Docker image** workflow and the
digest it adds to the GitHub release.

## Highlights

- **Share maps with players.** GMs publish selected layers, pins, labels, and
  drawings as a read-only map at `/c/<world>/maps/<map>`.
- **What's new.** Players see recent shared articles, session recaps, and maps
  across their campaigns, with current access re-checked on every read.
- **Saved.** Private bookmarks for campaign articles and published maps, synced
  across devices.
- **Notebook.** Private plain-text notes at `/player/notebook`, optionally linked
  to an article or map, with version-conflict recovery.
- **Security hardening.** Closed gaps in campaign search, request bodies, the
  public proxy boundary, container privileges, logs, and backups.
- **Sidebar fix.** World contents keeps a usable height on short screens.

## Changes since v0.4.11

### Player maps

- **Share with players** publishes an explicit snapshot of selected layers,
  pins, and annotations; nothing is selected by default. Players see that
  snapshot until the GM publishes again, so later edits stay private.
- Pins on unselected layers are excluded even if individually selected.
  Publishing requires the map image (and included layer images) to be shared
  with campaign players; the dialog can share them and records it in the audit
  log.
- The player view has pan, zoom, reset, and a keyboard-accessible pin list.
  Article links appear only when that player can read the linked article.
- Published maps are listed on campaign home; unpublishing hides them. World
  export still excludes player publications, so imported worlds start
  unshared.

### What's new

- `/player` shows the 20 most recent shared articles, session recaps, and
  published maps across the player's campaigns.
- Entries store no titles or links; the projection reads current content and
  re-checks access every time. Revoking access or unpublishing removes the entry
  without leaking its title.
- Candidate paging continues until 20 readable entries or exhaustion, so other
  players' shares cannot hide older readable updates.
- GM preview sessions see only the previewed world and no other account's
  activity.

### Saved bookmarks

- **Save/Saved** toggles on campaign articles and published maps.
- Bookmarks are private to the account, sync across devices, and appear under
  **Saved** on `/player`.
- Hidden bookmarks (revoked access, unpublished map, unreadable image, archived
  world) return if access is restored and never consume the 100-item limit.
  Deleting an article or map removes its bookmarks.
- Writes require a matching Origin, are idempotent, and reject GM preview
  sessions.

### Notebook

- `/player/notebook` provides private plain-text notes with search, campaign
  filtering, explicit save, and delete confirmation.
- **Take a note** on an article or map prefills the reference without copying
  campaign content.
- Notes store only the player's text; the campaign label and reference link are
  re-checked on read. Revoking access hides only the reference; the note stays.
- Optimistic versioning returns `409` with the current server copy. The editor
  keeps the draft and offers **Load latest**, **Keep my draft**, or **Copy my
  draft**. A version-conflict campaign change is adopted by **Load latest**.
- Saving text while a campaign is temporarily hidden does not detach the note.
  The 500-note limit is enforced atomically at creation.
- Navigation guards cover the player portal and reference links; the editor and
  note list lock while a save or delete is in flight.

### Security hardening

- **Campaign search** now excludes archived worlds and marks every response
  `private, no-store`.
- **Request body caps** apply before authorization parses JSON: 6 MB for
  world/resource bodies, 12 MB for map creation actions, including chunked
  requests without `Content-Length`.
- **CSP** disables inline event-handler attributes (`script-src-attr 'none'`),
  frames, media, and plugins while keeping the inline scripts/styles Next.js and
  reader custom CSS require.
- **Production boundary check** (`scripts/check-production-boundary.sh`)
  verifies loopback-only publishing, HTTPS origin, trusted proxy, no duplicate
  `:3035` server, security headers, and non-cacheable private responses. It
  fails closed and rejects non-HTTPS URLs and unsafe bindings (including mixed
  IPv4/IPv6).
- **Container privileges:** both Compose files drop all capabilities and set
  `no-new-privileges`; the server still runs as UID/GID `10001`. The documented
  ownership-repair command adds only `CHOWN`, `DAC_OVERRIDE`, and `FOWNER`.
- **Access matrix:** `tests/access-matrix-api.test.ts` covers anonymous,
  non-member, revoked-member, active-player, preview, and owner callers across
  search, readers, image bytes, notebook, bookmarks, activity, and export,
  including archived worlds, revoked images/articles, GM-only drafts, direct
  reads, and two-world preview isolation.
- **Logging:** migrated routes log an operation, error class, and allowlisted
  code only; Prisma automatic error logging is disabled in production. Some
  legacy author handlers still log raw errors and are documented.
- **Backups:** `scripts/rehearse-restore.sh` restores into a disposable volume
  and verifies integrity, migrations, ownership, permissions, database-referenced assets, and archive safety. Historical rolled-back migration rows
  are allowed; unfinished current migrations fail.
- **Dependencies:** pnpm is upgraded from 10.34.9 to 11.29.0 (install settings
  moved to `pnpm-workspace.yaml`, build approvals via `allowBuilds`). A fresh
  Trivy 0.76.2 scan of the release image reports **0 fixable findings** at any
  severity, down from two fixable MEDIUM findings in the pnpm-bundled CLI.
  Residual findings are recorded in `docs/security-scan-triage.md`.

### Workspace

- World contents in the sidebar keeps a 12rem minimum height, scrolls internally,
  and no longer overflows its frame on 800–900px-tall windows. The sidebar
  scrolls only when fixed chrome does not fit.

## Compatibility

- Four additive migrations: `MapPublication`, `PlayerActivity`,
  `PlayerBookmark`, and `PlayerNote`. No backfill is required.
- New APIs: `/api/maps/publish`, `/api/player/activity`,
  `/api/player/bookmarks`, `/api/player/notes`, and
  `/api/preferences/theme` (from v0.4.11).
- New pages: `/c/[worldSlug]/maps/[mapId]` and `/player/notebook`.
- No configuration keys are required. `WORLDFORGE_BUILD_REVISION` remains
  optional for source-built images.
- Source installations should upgrade pnpm to **11.29.0** to match the lockfile
  and `package.json`. The container image already pins it.
- The image still runs Node.js 22 and SQLite 3.54.1.
- Release scan: 0 fixable findings; 55 HIGH, 84 MEDIUM, 81 LOW, and 18 UNKNOWN
  findings have no scanner-listed fix and remain residual risks, not approved
  exceptions.

## Upgrade and rollback

Stop WorldForge and back up the database and asset directory together before
upgrading. Keep the existing volume, Compose project name, origin, and proxy
settings.

After image publication, set `WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.12` in
your pull-only Compose deployment, then run `docker compose pull` and
`docker compose up -d --wait` with the same Compose files you normally use. The
entrypoint applies the four migrations before starting the server. Verify login,
a representative world and image, campaign reading, a published map, and the
player portal.

Rollback requires the previous image and the matching pre-upgrade database and
assets backup; do not run an older image against a database that has received
these migrations. Do not remove the data volume. Run
`bash scripts/rehearse-restore.sh` against a recent backup after changing the
image or storage layout.

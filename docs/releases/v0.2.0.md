# WorldForge v0.2.0

This release adds player-only accounts and an invitation-based campaign join
flow. A GM can create an email-bound, one-use invitation link from the campaign
overview, copy it for the intended player, and cancel or refresh it. WorldForge
does not send invitation email. Links expire after seven days.

New players set a name and password when claiming an invitation. Existing users
sign in with the invited email; joining a campaign does not change their account
role or ownership of other worlds. Player-only accounts land on a dedicated
home page listing their campaigns.

GMs can manage members and grant access to individual articles, statblocks, and
images for selected members or all active members. Reader pages and search check
current membership and grants, while author APIs require world ownership.
Revoking a member also invalidates their selected-resource grants.

See the [player account guide](../player-accounts.md) for invitation, sharing,
recovery, and access details.

## Upgrade

Back up the SQLite database and asset directory before upgrading. The new
`PlayerInvitation` migration is applied automatically when the Docker container
starts. Existing accounts, memberships, and grants remain in place.

For an installation tracking `main`:

```bash
git pull
docker compose up -d --build
```

For an installation pinned to a release tag:

```bash
git fetch --tags
git checkout v0.2.0
docker compose up -d --build
```

For a non-Docker installation, run `pnpm db:deploy` before starting the updated
application. If you must roll back, restore the pre-upgrade database backup with
the matching application version.

# WorldForge v0.4.2

Security-hardening candidate for the Docker image. Publish only after review
and CI, then verify the image version/digest appended to the GitHub release.
No `0.4.2` registry availability is claimed by these notes alone.

## Changes

- Move the runtime from Node 22 on Debian 12 to Node 22 on Debian 13
  (`trixie-slim`). Continue supporting linux/amd64.
- Update the pinned pnpm version from `10.14.0` to `10.34.9`.
- Remove unused npm/npx and their bundled dependency tree from the runtime.
  Continue using pnpm, Prisma CLI and tsx for migrations and operations.
- Build release images with refreshed base-image metadata (`--pull`).
- Scan before publishing; block scanner failures, malformed reports, and
  fixable HIGH/CRITICAL findings. Retain full reports, including unfixed
  findings, as CI artifacts for 30 days. Add weekly/manual non-publishing scans.
- Extend image smoke checks to verify account setup/admin bootstrap without
  exposing setup tokens.

## Scan evidence and remaining risks

In a same-database Trivy `0.76.2` comparison with published `0.4.1`, the local
candidate reduced CRITICAL findings from **4 to 0**, HIGH from **86 to 51**,
and fixable HIGH/CRITICAL findings from **43 to 0**. The JavaScript findings
have no remaining HIGH/CRITICAL matches.

**51 HIGH OS findings remain**, spanning 13 advisory IDs, with no fixed Debian
version listed by the scanner. They include SQLite and system utility/library
matches; several have upstream fixes that Debian 13 has not packaged, while
two source-package findings concern absent components (homed and Archive::Tar).
Prisma embeds a separate SQLite copy that is not patched by the base-image
change. These findings are not approved exceptions or proof of safety. Docker Hub counts
may differ. See [Container security](https://github.com/emorgan33/worldforge/blob/v0.4.2/docs/container-security.md)
for the complete residual inventory, policy and coverage limitations. This
release is **not vulnerability-free** and does not establish runtime
exploitability or complete native-library coverage.

## Upgrade

No schema migration is added relative to `v0.4.1`. **Stop the service and take
a verified database-plus-assets backup before upgrading.** Preserve the same
Compose project, volume, UID/GID `10001`, origin and proxy-network settings.

After Docker publishing succeeds, update a published-image installation's
`.env` to `WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.2`, then run:

```bash
docker compose pull
docker compose up -d --wait
docker compose logs worldforge
```

If using a non-default Compose filename, include all existing `-f` options.
For a source build, select source tag `v0.4.2` and run
`docker compose up -d --build`. Never use `down --volumes` on real data.
Verify login, representative worlds/readers/images, a normal write, and local
admin/setup commands as applicable. The `pnpm` commands are unchanged; npm/npx
are intentionally unavailable inside the runtime image.

Rollback requires the older image and its matching pre-upgrade database and
assets. The existing `0.4.1` tag is not overwritten by this security update.
Production deployment is a separate operation; building or publishing this
candidate does not change a running installation.

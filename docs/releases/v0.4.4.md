# WorldForge v0.4.4

Security and documentation update. Image availability is confirmed only after
the **Release Docker image** workflow succeeds and the image tag/digest appears
in the GitHub release notes.

## Highlights

- Updates Next.js and `eslint-config-next` from `16.4.1` to `16.4.5`, addressing
  the November 3 Next.js advisories, including the SVG rejection bypass, and
  refreshes the lockfile.
- Completes the tracked wiki and operator guidance: 32 pages covering
  installation, upgrades, configuration, features, contributor workflows, and a
  verification record. The sidebar, Home page, and internal page/heading links
  are checked.
- Adds `pnpm docs:check` and CI coverage for required wiki pages, sidebar
  coverage, internal links, source owners, and verification labels. New checker
  regressions are part of the unit suite.
- No application data-model, API, or schema changes are included.

## Security notes

This release is **not vulnerability-free**. The image is rebuilt from this tag
with the updated Next.js dependencies, and the release workflow blocks fixable
HIGH/CRITICAL findings before publishing. Unfixed findings remain visible in the
retained scan report.

The residual container inventory documented for `v0.4.3` is the expected
baseline: 38 unresolved HIGH package matches in util-linux, ACL, and zlib with
no fixed Debian 13 version in the scanner database. Runtime mitigations reduce
exposure but do not patch those packages. See
[Container security](https://github.com/emorgan33/worldforge/blob/v0.4.4/docs/container-security.md)
for policy, evidence, limitations, and local scan commands. The workflow report
for this exact release is authoritative if counts differ.

## Upgrade

No schema migration is added relative to `v0.4.3`.

**Stop WorldForge and take a verified backup of both the SQLite database and the
full asset directory before upgrading.** Keep the same Compose project name,
`worldforge-data` volume, UID/GID `10001`, origin and proxy network settings.

For a published-image installation, set
`WORLDFORGE_IMAGE=emorgan33/worldforge:0.4.4` in `.env`, then run:

```bash
docker compose pull
docker compose up -d --wait
docker compose logs worldforge
```

For a source-build installation:

```bash
git fetch --tags
git checkout v0.4.4
docker compose up -d --build
```

Native source deployments that want the patched SQLite engine must run
`pnpm sqlite:build` after installing dependencies; ordinary `pnpm install`
leaves the driver's bundled SQLite in place. The supported Docker image always
builds SQLite 3.54.1.

Existing native millisecond timestamps remain readable; no data rewrite is
required. Verify login, representative worlds/articles/search/images, a normal
write, and backup tooling after upgrading.

Rollback requires the older image/source **and** the matching pre-upgrade
database-and-assets backup. Do not run an older application against a database
that has received newer migrations, and do not use `down --volumes` on real data.

# WorldForge v0.4.13

This release reorganizes the author workspace: workspace destinations stay in a
stable far-left rail while World contents moves into a dedicated, contextual
explorer. Large article trees get their own browsing space, focused writing can
hide that space, and pinning keeps it available in other tools. Narrow layouts
get a full drawer instead of a cramped second column. Public and campaign
reader navigation are unchanged.

Image availability is confirmed only by the **Release Docker image** workflow
and the digest it adds to the GitHub release. Check that workflow before
choosing an image version.

## Highlights

- **Contextual explorer.** World contents opens when entering Articles
  (including reading, editing, and category management) and stays available
  through those views.
- **Pinnable.** **Pin world contents** keeps the explorer visible across Maps,
  Sessions, and other tools. **Collapse world contents** hides it for focused
  writing; an explicit collapse is not overridden by later article selection.
- **Persistent preferences.** Pin and collapse choices survive reloads. Branch
  expansion, selection, and tree scroll position survive hiding and reopening,
  and reset on a world switch.
- **Narrow layouts.** A labelled **Browse world** control opens the explorer as
  a focus-managed drawer. Escape closes it and restores focus; accepted article
  or category navigation closes it, while a declined discard keeps it open.
- **Toolbar actions.** Search this world and New article remain reachable with
  the explorer open or closed. The template picker is now a keyboard-accessible
  modal with focus containment and restoration.
- **Accessible rail.** Expanded and compact modes share active-destination
  state, so Articles remains marked while browsing or editing an article.
  Selected articles and categories are identifiable to assistive technology.

## Changes since v0.4.12

### Workspace navigation

- The sidebar is now a workspace rail only: branding, world switching,
  destinations, utilities, and admin access. The article/category tree is no
  longer stacked with those app-level links.
- The new explorer reuses the existing `ArticleTree`; article/category
  navigation, drag-and-drop, busy states, error messages, and keyboard move
  controls retain their behavior.
- World contents, Search this world, and New article are available from the
  workspace toolbar. The explorer toggle sits at the left of the toolbar, next
  to the rail; the remaining toolbar actions stay right-aligned.
- Organization errors appear in the explorer and, when it is hidden, in the
  workspace so a failed move or reorder stays actionable.

### Accessibility

- The explorer drawer and template picker are named modal dialogs with initial
  focus, Tab/Shift+Tab containment, Escape dismissal, and focus restoration.
- Background regions are inert while either modal is open. The rail is not
  inert while it is itself the open navigation drawer.
- Compact rail destinations have hover and focus labels and visible focus
  rings. The mobile rail still exposes search, player view, and sign out.

### Compatibility

- No database migrations, backfills, or new configuration keys. The database
  and asset directory format are unchanged.
- Public (`/w/...`) and campaign (`/c/...`) reader trees, search, breadcrumbs,
  and visibility filtering are untouched.
- Existing theme tokens and world-switching/unsaved-edit safeguards are
  preserved. A declined discard leaves the current view and drawer intact.
- The image still runs Node.js 22 and uses the same patched SQLite runtime.

### Verification

- `pnpm lint`, `pnpm build`, `pnpm exec tsc --noEmit`.
- 398 unit tests, 99 service tests, 122 HTTP tests, 94 browser tests, and 4
  production authentication smoke tests on isolated storage.
- Focused browser coverage for contextual visibility, pin/collapse persistence,
  selection and branch retention, drawer focus/Escape/inert behavior, template
  picker keyboard operation, and the explorer toggle position.
- Rendered desktop and narrow layouts inspected with long titles, deep nesting,
  empty worlds, and organization errors.

## Upgrade and rollback

No migration or data step is required. Upgrade by deploying the new release
image or building the tagged source and restarting the service. Rollback is the
matched code/image only; restore the pre-upgrade database only if a later
release changed the schema. Confirm the health check, `/login`, the author
workspace, and one representative world after upgrading.

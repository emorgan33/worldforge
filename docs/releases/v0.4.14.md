# WorldForge v0.4.14

This is a packaging-only patch release on top of v0.4.13. It restores the
container release gate by applying the Debian security fix for `libzstd1`
(`CVE-2026-124851`) in the image. Application behavior, the database schema, and
reader access rules are unchanged from v0.4.13.

**Do not rely on a v0.4.13 image.** Its **Release Docker image** workflow failed
the fixable HIGH/CRITICAL gate before publishing version or SHA tags. Use
v0.4.14 for the contextual World Contents explorer and its accessibility fixes.
Image availability is confirmed only by this release's **Release Docker image**
workflow and the digest it adds to the GitHub release.

## Changes since v0.4.13

- The image now installs `libzstd1` at the Debian security version
  `1.5.7+dfsg-1+deb13u1` instead of leaving the unpatched Debian base version.
  The dhi.io backport repository remains in place for the reviewed SQLite,
  ncurses, and zlib packages; its higher `libzstd1` candidate is explicitly
  overridden so the scanner-verified Debian fix is installed.
- No new vendor evidence is claimed for `libzstd1`: the finding is resolved by
  the installed fixed version, not by a disposition.
- A local Trivy 0.76.2 scan of the rebuilt image reports **0 fixable findings**;
  55 HIGH, 84 MEDIUM, 81 LOW, and 18 UNKNOWN findings have no scanner-listed fix
  and are recorded in [the scan triage](../security-scan-triage.md).

## Carried forward from v0.4.13

- World contents is a contextual, pinnable explorer beside the workspace rail,
  with a focus-managed drawer and keyboard-accessible template picker on narrow
  screens.
- Workspace toolbar actions and the left-aligned explorer toggle; reader
  navigation, theme tokens, and unsaved-edit safeguards unchanged.

## Compatibility

- No migrations, backfills, or configuration keys. The database and asset
  directory format are unchanged.
- Node.js 22, pnpm 11.29.0, and the patched SQLite runtime are unchanged.
- Upgrade by deploying the new image or building the tagged source and
  restarting. Rollback to the previous code/image is safe because no schema
  changed.

## Verification

- `pnpm lint`, `pnpm build`, `pnpm exec tsc --noEmit`, 398 unit tests, 99 service
  tests, 122 HTTP tests, 94 browser tests, and 4 production authentication
  smoke tests were run for the v0.4.13 feature candidate.
- The rebuilt v0.4.14 image passed `scripts/verify-vendor-patches.sh` and
  `scripts/scan-image.sh` locally with `fixableHighCritical: 0`; the release
  workflow re-runs both gates on `linux/amd64` and `linux/arm64` before
  publishing.

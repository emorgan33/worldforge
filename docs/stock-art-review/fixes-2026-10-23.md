# Corrections to issue #7 implementation review

The six findings in the [implementation review](implementation-review-2026-10-23.md)
are addressed. Human rights, collection/placement, full accessibility, and
withdrawal-drill sign-offs remain open. No candidate has been approved by this work.

## Behavior changes

- **Portable provenance:** imports validate bounded JSON, matching entry ID and
  version, usable credit text, required-credit/placement values, and safe
  license/source/creator links. Invalid artwork is skipped with an explicit
  warning; its image is never imported without attribution. Image and provenance
  database writes are transactional, so provenance failures leave no usable
  image row. V1 imports carrying unsupported provenance are refused explicitly.
  Imported origin is always `IMPORTED_DECLARATION`, including when a source
  snapshot claims approval.
- **Placement descriptions:** author, public, and campaign home/article views
  retain custom descriptions, explicit decorative empty strings, and null/title
  fallbacks. A global cover fallback carries its own description. Revoked assets
  do not render their image or description.
- **Legacy exports:** the v3 guard includes retained revision images and
  descriptions, including decorative empty strings. V2 is an explicit complete
  backup: filtering flags return HTTP 400 with guidance to use v1 when the world
  supports legacy export. V3 remains the default complete portable format.
- **Complete reader attribution:** all applicable provenance records survive
  projection and credits retain links and modification notices. Complete
  identical requirements are deduplicated; distinct requirements are preserved.
  Body, cover, and portrait adjacent credits appear beneath the figure. World
  and article pages include credits for readable background/category artwork.
  The reader heading is **Artwork credits**.
- **Pending review:** catalog rights now have an explicit `reviewStatus`.
  Production selection requires `approved` with a named, non-placeholder
  reviewer and date. Missing status is pending, not implicit approval.
  Development permits pending candidates for review and labels them **Pending
  human review — not verified**. New pending selections store `PENDING_REVIEW`;
  no application path promotes an imported claim to reviewed provenance.
